# SEO, AIO, and GEO implementation

## Content architecture

The platform and capability hubs support commercial discovery. Product pages answer the distinct questions behind attack path analysis, identity security, and cloud security posture. Team solution pages translate these capabilities into practical review workflows. Articles and guides form three educational clusters: connected attack paths, machine identity / least privilege, and CSPM versus attack paths. Related links connect educational content to the appropriate capability and team pages.

The initial keyword map is qualitative, based on topic and intent. No live search volume, competitive difficulty, rank, or AI citation metrics are claimed. This is a fictional company; external reputation and actual customer evidence do not exist.

## Crawl and index foundations

- Static server-generated HTML containing complete copy and internal links.
- Unique page titles and descriptions, one main H1, canonical URLs, and contextual breadcrumbs.
- XML sitemap and robots.txt generated for the configured origin.
- Open Graph and Twitter metadata with a 1200×630 social image.
- Organization, WebSite, WebPage/CollectionPage/AboutPage/ContactPage, BreadcrumbList, and BlogPosting JSON-LD reflecting visible content.
- No invented ratings, customer outcomes, certifications, Product offers, or FAQ rich-result promises.
- Responsive optimized images, meaningful alt text, dimensions, self-hosted fonts, minimal JavaScript.

## Readability for AI-assisted discovery

Articles provide self-contained explanations, mechanism-based headings, definitions, limitations, visible authorship/date, and links to primary references. Comparisons distinguish configuration findings from connected access paths. Synthetic product examples stay separate from evidence about real security concepts. Downloadable review templates add original utility beyond marketing summaries.

An optional llms.txt indexes public site sections. It is an informational aid, not a prerequisite for AI visibility. Google's guidance says normal SEO fundamentals apply to AI features and does not require a special AI schema or text file. No implementation guarantees rankings, indexing, AI Overview inclusion, or citation by ChatGPT, Perplexity, or another system.

Primary guidance reviewed:

- [Google: AI features and your website](https://developers.google.com/search/docs/appearance/ai-features)

## Deployment checks

Build with the real SITE_URL, verify that canonical and sitemap origins match, and confirm public indexability on the deployed host. Add Search Console and measure real traffic only after publication. Lighthouse is a laboratory test; field LCP, INP, and CLS need actual visitor data. TBT must not be reported as measured INP. Real claims require real product evidence.
